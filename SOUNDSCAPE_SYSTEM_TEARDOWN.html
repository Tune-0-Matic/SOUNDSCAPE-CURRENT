Most-misread setting

The window/size/mode=3 value is fullscreen. Godot's enum is 0=windowed, 1=minimized, 2=maximized, 3=fullscreen, 4=exclusive fullscreen. Fullscreen covers the taskbar, which is why the program looks correct at boot and clips at the bottom after a monitor move (§5.5).

1.2 Design principles

  • Single scene. player.tscn, 117 authored nodes, one root script. No inherited or instanced sub-scenes.
  • No autoloads. Nothing in [autoload]. Every subsystem is a child node reached by walking down from MediaPlayer.
  • No plugins or addons. No addons/ directory, no [editor_plugins].
  • No version control. No .git directory exists, despite .gitignore and .gitattributes being present. Review is the only safety net.
  • No external GDScript dependencies. The only runtime dependency is ffmpeg / ffprobe on PATH, used for FLAC transcoding and tag reading.
  • One source of truth per parameter. Where a value appeared in two widgets, one was removed rather than synchronised.
  • Nothing writes to AudioServer from inside an input callback. Every control sets a dirty flag; the bus is updated once per frame.

The “CPU” figure is frame time, not processor share

The STATS panel reads CPU.....16.7 MS/FRAME @ 60 FPS. It is deliberately not a percentage. Godot exposes no system-wide CPU percentage and no per-process CPU time, and Performance.TIME_PROCESS proved untrustworthy here — sampled against real frame time it reported 43.55 ms of process time inside an 18.06 ms frame, which is impossible. A percentage built on it read 377–999 %. The panel now reports the delta _process is handed, which is the frame by definition.

Mix rate: requested 96 kHz, delivered by the device

project.godot sets driver/mix_rate=96000. The actual rate is whatever the output device negotiates: measured 48,000 Hz in this run, and 96,000 Hz in others on the same machine. The status ticker prints the live value (MIX %d HZ) rather than the requested one, so the UI never claims a rate the hardware is not running.

SECTION 03Audio Pipeline & DSP Engine

3.1 Decode path

AudioEngine.request(i) is the single entry point.

request(i)
  ├─ _token += 1                       monotonic; only the newest request is honoured
  ├─ preloaded && path matches? ──────► _deliver(token, path, stream)      [no I/O]
  └─ WorkerThreadPool.add_task:
         decode(path)                  format-specific
         metadata(path)                ffprobe, ~55 ms
         _deliver.bind(...).call_deferred()   ← back on the main thread

_deliver() drops the result if token != _token, so a fast double-click cannot let a superseded decode hijack playback. On success it emits track_ready and immediately warms the next track.

Format handling
FormatPath
mp3AudioStreamMP3.load_from_file()
oggAudioStreamOggVorbis.load_from_file()
wavAudioStreamWAV.load_from_file()
flacffmpeg → raw s16le → hand-written RIFF header → AudioStreamWAV, cached in user://

Gapless preload

_preload() decodes and probes on the worker. The probe is not incidental: without it, _deliver() fell through to metadata() on the main thread and spawned ffprobe there — measured 54 ms, 3.3 dropped frames, on every gapless transition. With the probe warmed, the same call costs 0.02 ms. Cost: one decoded stream held in RAM, ~90 MB for a four-minute 96 kHz stereo track.

The WAVE_FORMAT_EXTENSIBLE trap

Silent failure

Godot 4.7 has no FLAC decoder — AudioStreamFLAC does not exist. Above 48 kHz, ffmpeg's WAV muxer emits WAVE_FORMAT_EXTENSIBLE (fmt tag 0xFFFE, 40-byte fmt chunk), which Godot's parser rejects: load_from_file returns null with no error, presenting as “the track just will not switch”.

The fix is to never let ffmpeg mux. Raw s16le is piped out and a canonical 44-byte header is written by hand (16-byte fmt chunk, wFormatTag = 1). Verified loading at 44.1 / 48 / 96 / 192 kHz. CHUNK = 1 << 20 streams the copy so a 90 MB wav never sits in RAM twice.

Cache files are user://pcm_<hash>.wav, pruned after every scan against what is on disk — unchecking a folder must not force a re-transcode when it is re-checked. A cached file of ≤ 44 bytes is treated as a miss and re-transcoded (a transcode killed mid-write used to load as null forever).

3.2 Metadata, tags and thread safety

metadata() shells out to ffprobe for sample rate, channels, bit depth, codec, title, artist, album and musical key. Results never change for a file, so they are cached for the session in _meta.

_meta is written from worker threads and read from the main thread, and a Godot Dictionary is not thread-safe — an insert can rehash under a concurrent read. It is guarded by _meta_lock: Mutex with a deliberate protocol:

lock → read cache → unlock
   … probe unlocked (~55 ms) …
lock → if another thread already published, take theirs; else publish ours → unlock

The lock is never held across the probe. Holding it would serialise every worker and block the main thread outright — reintroducing the stall the preload fix removed. Two threads may therefore probe the same file; that costs one duplicate ffprobe and nothing else, because the first writer wins and every caller ends up holding the same Dictionary instance. Temp JSON is named probe_<pathhash>_<threadid>.json so concurrent probes of the same file cannot clobber one another.

Verified under 24 concurrent workers on 6 files: 144 results, 0 content mismatches, 6 cache entries, 0 leftover temp files.

Encoding trap

OS.execute() decodes subprocess output using the system ANSI codepage, which mojibakes any non-Latin tag (中原 came back as ä¸­åŽŸ). ffprobe writes its JSON to a file with -o; FileAccess reads it back as UTF-8 correctly.

Key tags

The key is read from the file's own tag during that same probe — matched case-insensitively against KEY, INITIALKEY, INITIAL_KEY, TKEY, across both container and stream tags. Whatever the tagger wrote is normalised:

Tag normalisation

The Camelot number is a circle-of-fifths position with C major pinned at 8B; a minor key borrows the number of its relative major, which is the entire point of the notation — same number means compatible. A tag that will not parse is shown verbatim rather than blanked. Untagged files show KEY: -- and cost nothing.

Removed by design

Spectral key estimation was built (Goertzel chromagram + Krumhansl-Schmuckler, verified exact on synthetic material) and then removed: it cost ~1 s of tight-loop CPU plus a second concurrent ffmpeg per track, to produce a guess. Tags are free and authoritative.

3.3 Master bus chain — slots 0–12

Inserted at ascending slots from the head of the bus, so the analyser appended by AudioDirector always ends up last. The visualizer therefore shows post-EQ audio: what you see is what you hear. Bus effects also run before bus volume is applied on send, so none of this is affected by the VOL knob.

Every effect is inserted disabled; add_bus_effect enables by default and the per-frame push does not run until frame 1, so without this the chain would process a frame or two before anything had decided it should be on.

Three ordering decisions are load-bearing:

  1. The DJ filter is at the front. Filtering after the reverb would leave the tail unfiltered and the sweep would not read as a cut.
  2. Time-based effects follow the tone stage, so they reverberate the shaped signal.
  3. Boost and limiter are effects, not bus volume. Bus volume is applied after the chain on send, so a limiter placed anywhere else could never catch clipping the rack in front of it caused.
Invalidation trap

Adding or removing any bus effect rebuilds every effect instance on that bus, silently invalidating the analyser handle AudioDirector cached in its own _ready() — levels then read 0.0 forever with no error. Children are ready before their parent, so _setup_eq() must call _director.rebind() after building the chain. Note that set_bus_effect_enabled() does not rebuild instances; only add/remove does.

Enabled-slot verification. With EQ OFF and no FX engaged, a live capture shows exactly one enabled slot: 12:SpectrumAnalyzer. Everything else genuinely unloads at rest.

DJ filter and its dead centre

CUT_DEAD = 0.04 — a ±4 % detent around 0.5 where neither filter is in circuit.

cut < 0.46 →  LOW-PASS,  f = 80 · (20000/80)^(t)      t = cut/0.46
cut > 0.54 →  HIGH-PASS, f = 20 · (8000/20)^(t)       t = (cut−0.54)/0.46
otherwise  →  BYPASS

Both sweeps are logarithmic. A linear sweep spends most of its travel above 10 kHz, where nothing is, and crosses the whole audible bass range in the last few pixels. A click within 6 % of centre snaps to exactly 0.5, because hitting an 8 %-wide detent by pixel while sweeping is not something a hand can do.

Behavioural change

T-BASS and BBE are independent of the EQ mode. They used to be gated on mode != OFF, which made the rack faders silently inert whenever EQ read OFF — the fader moved, the readout changed, nothing happened to the sound, with the explanation two tabs away. They now behave exactly as boost_db always has: the drive stage is the hardware colour of the signal, not part of the equalizer curve.

Pitch / tape

pitch_scale = tape · 2^(key_semi / 12)

TAPE SPEED and KEY SHIFT are two views of one AudioEffectPitchShift — tape in playback ratio, key in semitones, multiplied. A second shifter would double the most expensive thing on the bus to say the same thing twice. At TAPE 1.00× and KEY 0 ST the product is exactly 1.0 and the effect is switched off, not merely at unity. Verified: +7 ST → 1.4983, −12 ST → 0.5000, tape 1.25 alone → 1.2500.

Never touched

AudioStreamPlayer.pitch_scale is deliberately never used. Driving it puts every frame of a 96 kHz stream through the realtime resampler — measured as audible stutter.

Delay

tap1: delay = ms,        level = 20·log10(wet),      pan = −0.4
tap2: delay = ms × 1.5,  level = tap1 − 3 dB,        pan = +0.4
feedback: active if fb > 0.005, level = lerp(−30 dB, −3 dB, fb)
dry = 1.0

The 1× / 1.5× offset with opposed panning is the stereo in “stereo delay”; one centred tap is an echo, not a spread. Feedback never reaches unity — at 0 dB a delay line never decays and the tail builds until it clips. −3 dB at the top is still ~10 audible repeats.

Reverb

room_size = rev_room
damping   = rev_damp
wet       = rev_wet
dry       = 1.0 − rev_wet          a true crossfade

A wet send bolted onto a full dry signal would make the level climb with the mix knob, so WET MIX would read as a volume.

Equalizer — 16 lanes onto 21 bands

Godot ships EQ6, EQ10 and EQ21; there is no EQ16. The 16 UI lanes are a control curve, sampled and linearly interpolated onto EQ21's band gains:

for band b in 0..20:
    t = b / 20 · 15
    i = floor(t);  f = t − i
    gain[b] = lerp(curve[i], curve[min(i+1, 15)], f)

Lane centres run 32 Hz → 16 kHz logarithmically: f(i) = 32 · 500^(i/15). Only every fourth lane is labelled — 16 stacked captions is unreadable at that width.

Range GAIN_MIN −18 dB … GAIN_MAX +18 dB. Modes: OFF (bypass), EZ (three macros weighted onto the same curve with raised cosines, so bands overlap smoothly rather than stepping at the crossover), ADVANCED (all 16 + 8 preset slots, EQ_SLOTS = 8).

ADAPT spreads a change across neighbours with a Gaussian of ADAPT_SIGMA = 1.6 lanes — the immediate neighbour lands at ≈0.82 of the dragged lane, the third out at ≈0.17. The spread is measured from a snapshot taken when the drag began; working from live values would compound the curve into a spike over a long drag.

BOOST_MAX = 24 dB (16× amplitude). The hard limiter behind it is what makes that safe: past the clipping point it saturates instead, so the top of the dial trades dynamics for loudness rather than breaking up.

3.5 Spectrum analysis & beat tracking

AudioDirector reads 32 bands (BAND_COUNT) spread logarithmically from F_MIN = 30 Hz to F_MAX = 16 000 Hz. That part is nearly free and always runs — it feeds the visualizer. The tempo machinery on top is off by default (track_tempo = false) because the fit sweeps ~560 candidate periods every 0.5 s on the main thread and nothing but the BPM readout consumes it.

BUFFER_LENGTH = 0.05 is measured, not chosen

ValueResult
0.10beat clock −169 ms, sd 196 — never locks
0.05+6 ms, sd 8
0.03tempo confidence collapses 0.87 → 0.29

Onset detection

Spectral flux is taken from the low 11 bands only (FLUX_BANDS = 11, ≈30–250 Hz: kick and low bass), kick-weighted 1 + 2·(1 − i/32). Full-spectrum flux tracks a click track fine but smears on a real dense mix — measured 0.11 confidence on a pop track versus a usable lock from these bands.

An onset is flux above the mean of a trailing FLUX_WINDOW = 43 frame window (≈0.7 s at 60 FPS) × sensitivity (default 1.5), plus a 0.12 s debounce (caps at ~500 onsets/min). There is deliberately no local-peak test: it rejected the rising frame of short transients and starved the fit — 7–11 onsets where 15–30 were present.

Tempo fit

Onsets are treated as impulses and the DFT magnitude taken at each candidate tempo:

for bpm in 60.0 … 200.0 step 0.25:            561 candidates
    period = 60 / bpm
    re = Σ cos(2π·t/period),  im = Σ sin(2π·t/period)
    magnitude = √(re² + im²) / n
phase = fposmod(atan2(im, re)/2π · period, period)

Phase-invariant, and the complex argument hands back the grid phase for free.

Octave correction: an eighth-note grid scores as well as the quarter-note one, so if half the winning tempo scores above 0.8× the best, the slower reading wins.

Phase easing: once locked, phase eases toward each new fit at PHASE_EASE = 0.25 rather than snapping. A hard re-anchor every fit jittered the clock to sd 89 ms at 90 BPM; this is a PLL-lite that stays predictive while still following real drift. History: HISTORY = 10.0 s of onsets, MIN_ONSETS = 6 below which a fit is noise.

True song clock

song_time = player.get_playback_position()
          + AudioServer.get_time_since_last_mix()
          − AudioServer.get_output_latency()

This removes mix-ahead and output latency. It does not cover the analyser's own trailing-buffer lag, which is why onsets are timestamped back by a separate calibration constant, onset_lag = 0.066, while the beat clock runs on true song time. It is an exposed knob, not a magic number: 0.035 overcorrects to +42 ms.

time_to_beat() returns seconds until the next predicted beat, so animation can be led rather than triggered after the fact. Bar indices derive from the absolute beat index, so a re-lock re-anchors bars to the music — bars emitted is deliberately not beats ÷ 4.

A “pixel” in a bar is genuinely one buffer texel blown up to a 4×4 block. Every coordinate in the drawing code is snapped to an integer — at this resolution a half-pixel smears a cell edge and loses the entire point of the viewport. Column edges are snapped independently so bars tile exactly; some end up 1 px wider, which is correct for pixel art and is what stops a dead strip appearing on the right at awkward widths.

crt.gdshader is a canvas_item shader on the container, not the viewport. scan_period2–124.0Screen-space px per scanline pair
bleed0–10.25How much of the glow's alpha survives
 
sum = (8 taps around a ring at ±px, ±0.7px) × 0.125
col = base.rgb + sum.rgb · glow_amount
a   = clamp(base.a + sum.a · glow_amount · bleed, 0, 1)
row = mod(FRAGCOORD.y, scan_period)
col *= mix(1 − scan_strength, 1, step(scan_period·0.5, row))

The blur is an 8-tap ring rather than a separable Gaussian: a Gaussian would be cleaner but needs two passes, and on a 1 px wireframe over black the two are indistinguishable.

Invisible-bloom trap

Glow must carry alpha. The viewport is transparent. Adding only sum.rgb produces a bloom that is mathematically present and completely invisible, because destination alpha is still zero everywhere the source was.

Hard alternating rows via step(), not a soft sine wash — distinct, like a real monitor.

4.3 Normalization pipeline

All ten modes read the same 32 magnitudes and pass through the same four stages. The constants were measured against this library, not guessed.

  1. dB conversion. linear_to_db(max(level, 1e-7)). Linear amplitude leaves a real mix pinned to the floor; dB is the only mapping that spreads it over the full height.
  2. Spectral tilt. + tilt_db · i/32, default 20 dB, cancelling the library's natural ≈39 dB slope (band 0 peaks −7 dBFS, band 28 −46). At tilt 0 the top two-thirds of the display never leave the floor.
  3. Auto-gain. Mandatory, not polish — masters here range −7 to −32 dBFS peak. _agc = max(max(_agc − 8.0·dt, top), −50): tracks the loudest band instantly, falls at AGC_FALL = 8 dB/s, floored at AGC_FLOOR = −50.
  4. Ballistics. Attack 0.22→0.95, release 0.04→0.40, peak-hold fall 0.15→1.30, all driven by one SPEED knob. Attack always outruns release — equal rates read as flicker rather than as an EQ, so the two ranges never cross.

Window span: lerp(80, 30, sensitivity) dB.

Frame-rate independence

Anything that used to advance “once per _process” ran 2.4× faster at 144 FPS than at 60. REF_FPS = 60.0 is the reference every per-frame constant was tuned at.

_fps_lerp(a, b, k, dt) = lerp(a, b, 1 − (1−k)^(dt · REF_FPS))

At exactly 60 FPS the exponent is 1 and this reduces to the original lerp, so the tuned feel is preserved rather than re-guessed. _due_steps(dt) converts elapsed time into whole steps for the discrete effects (waterfall rows, grid history, fire propagation), carrying the remainder, capped at 4 so a frame hitch replays a few steps instead of hundreds.

Suspension

The edge list is built once in _init() and never rebuilt — the body does not deform. Motion is a transform offset applied at draw time:

offset.y = sin(t·47.0)·0.009 + sin(t·31.3)·0.0054      jitter_amp = 0.009
offset.x = sin(t·0.37)·0.11  + sin(t·0.23)·0.0605      sway_amp   = 0.11

Detuned sine pairs, so the cycle never visibly repeats. Amplitudes are deliberately tiny: the road is already moving, so the car only has to stop looking welded to the screen.

SECTION 05UI System, Styling & Responsive Layout

5.1 The skin system

Eleven schemes: WIN98, MAROON, MIDNIGHT, AMBER, TOKYO, TERMINAL, ICE, VAPORWAVE, MIAMI, C64, HAZARD.

The in-place mutation trick. Every stylebox in player.tscn is a shared sub-resource. Skins.apply() mutates those resources directly — sb.bg_color = s.panel — so a single write repaints every panel that references it. No theme rebuild, no node walk, no per-node override.

This is also why the FX rack (built entirely in GDScript) repaints with every skin for free: it creates no styleboxes of its own. A locally-constructed one would be the single panel stuck on WIN98 grey.

Each scheme defines window, panel, border, header, header_text, text, screen, screen_text, accent, and optionally accent2. Where accent2 exists it drives the filled indicators (progress bars, fader tracks, list selection) while accent keeps the text highlights — that split is what makes the two-tone skins read as two-tone instead of one hue smeared over everything.

Theme type variations rather than per-node overrides: Header and Screen derive from PanelContainer; HeaderLabel and Green from Label. Every stylebox is a StyleBoxFlat with corner radius 0 and a 1 px border. Nothing is rounded; nothing has a shadow.

Type-check is not enough

Skins._flat() must test has_stylebox() first. For a missing entry Godot does not return null — it hands back a fresh default StyleBoxFlat, which sails through an is StyleBoxFlat test. Type-checking alone caught only a wrong-typed entry and stayed silent on a renamed or deleted one, which is exactly the case the warning exists for. Audited across all 11 schemes: no dead entries today.

5.2 Typography

Px437_IBM_BIOS.ttf — a vector reconstruction of the 8×16 VGA ROM font from the IBM PC BIOS. Theme default_font, default_font_size = 16, the size at which its 16 px glyph cells land on exact pixel boundaries.

CJK fallback. Px437 covers code page 437 — box drawing, a few accents, no Japanese. The library contains tracks by 中原めいこ, which would render as tofu. _setup_pixel_font() attaches a SystemFont chain at runtime:

The fallback carries the same settings. Without that, a Japanese album name renders smooth and grey beside hard black Latin text in the same label — which reads as a bug, not as a fallback.

Cursor. A 12×19 arrow built in code from an ASCII-art constant (# outline, . fill, space transparent), nearest-scaled ×3 (CURSOR_SCALE), hotspot at pixel (0,0). Drawing it rather than shipping a PNG keeps it one file and lets a constant decide how chunky the pixels read.

Not a regression

LARGE cannot reach 3:1. It lands at 0.694 because the 575 px sidebar floor is a hard minimum. The previous BoxContainer gave 0.696 for the same reason — minimum size beats stretch ratio.

The split solver

SplitContainer ignores size_flags_stretch_ratio; it positions the divider from split_offset, a delta from a default set by the children's minimum sizes. That default cannot simply be read — measured, split_offset = 0 is itself clamped and reads 102 px short. The relationship is otherwise exactly linear, slope 1.0:

off=0     → first = 1325   (clamped)
off=−200  → first = 1227
off=−400  → first = 1027
off=−1000 → first =  427        ⇒ true default = 1427

So _split_to_fraction() solves by fixed-point iteration: with slope 1 it lands exactly in one correction when the target is reachable, and stops itself the moment the offset stops changing — which is what a clamped mode does. Two frames per pass (the container re-sorts a frame after the offset is set). A _split_gen token drops superseded runs, because switching feed size twice quickly leaves two coroutines both writing the divider.

split_frac is stored as a fraction, not pixels. The stretch base pins the viewport width at 1920 on every screen, so only the height changes — 1080 on the landscape panel, 3413 on the portrait one. A single stored pixel offset was being applied to a horizontal split across 1920 and a vertical split across 3413; it could not be correct in both. Verified across all three monitors: 0.400 requested, 0.400 measured on each.

5.4 Detachable windows

embed_subwindows=false makes Window nodes real OS windows. This is global — there is no per-window override — and it also promotes the FOLDERS file dialog to a native window.

The settings screen. The TBS tab is hidden from the tab bar (set_tab_hidden); all ten of its rows pop out into an OS window via the [ TBS SCREEN ] button on STATS. The node is hidden rather than deleted because it is where the rows go home to when the window closes. Window: 640 × 620, min 430 × 470, centred on the usable rect of its screen.

Tear-off tabs. drag_to_rearrange_enabled = true is what makes a tab draggable at all. The tab under the cursor is recorded on NOTIFICATION_DRAG_BEGIN; on DRAG_END, if gui_is_drag_successful() is false and the cursor is outside the TabContainer rect, the tab tears off into its own window. Size 620 × 720 landscape / 560 × 1000 portrait, clamped to the screen's usable rect, with the minimum derived from the panel itself — measured, the tabs need 532 / 480 / 412 / 336 px, so the original fixed 380 px floor let EQ be dragged 152 px narrower than it can draw in. Padding drops 6 px → 1 px below 520 px wide.

Restoring uses a canonical order map, not a stored index: a stored absolute index goes stale the moment a second tab is torn off. Verified with three tabs torn off and restored in a different order than they left.

Measured, corrected three times

Reparenting and %UniqueName. reparent() preserves a moved node's whole subtree of unique-name registrations when that node has an owner. A runtime-created carrier with no owner loses them for its descendants — silently, so %EqMode simply stops resolving and the next _refresh_eq() dies on a null. _restore_unique_names() re-toggles the flag over the moved subtree as insurance, since the FX tab is built at runtime and has no owner.

The program boots fullscreen, which covers the taskbar, so nothing is hidden at rest. Shift+Win+Arrow moves the window while leaving that mode in place, and the taskbar then draws over the bottom 72 px — exactly the status bar plus half the transport deck, gone with nothing to say so.

_refit_window_to_screen() polls the current screen index each frame (Godot exposes no “window changed screen” notification). On a change, if the window hangs past the usable rect on either axis, it switches to borderless MAXIMIZED. The first reading is recorded and never acted on — at boot the window is deliberately 72 px past the usable rect.

Why that repair and not another, all measured:

  • WINDOWED is unreachable from the boot fullscreen state on this build — setting it reports EXCLUSIVE_FULLSCREEN back and window_set_size is refused outright.
  • Re-asserting FULLSCREEN on the new screen changes nothing; still 72 px under.
  • MAXIMIZED lands inside the usable rect on all three screens, portrait included.
  • BORDERLESS keeps the chromeless look the fullscreen boot has.

F11

F11 toggles the OS window. Entering saves the current geometry to _windowed_rect (session-only — a saved rect that no longer fits the current monitor arrangement is worse than none) and sets fullscreen. Leaving clears borderless, goes via MAXIMIZED, then requests WINDOWED, verifies the result, and falls back to borderless MAXIMIZED if the release did not take. Geometry is restored exactly:

F11 → fullscreen    saved rect = [P:(0,419), S:(1920,1006)]
F11 → windowed      restored   = pos (0,419) size (1920,1006)

ESC unwinds whichever kind of full screen is on — the in-app FULLSCREEN feed first (hides chrome), then the OS window mode. The two are separate and stack.

Both paths call _relayout_for_window(): two frames deferred (the window has not finished resizing when the mode change returns), then _update_orientation() re-reads the viewport, re-picks portrait/landscape, recomputes the sidebar floor and re-applies the feed — which re-solves the split from its fraction, so the divider lands proportionally right at the new size. The SubViewport follows on its own via stretch_shrink.

Measured on all three monitors in fullscreen: viewport aspect equals window aspect in every case (no letterboxing), and the FULLSCREEN feed fills the workspace exactly.

Zero-width bar trap

A Control not yet laid out still receives input, and computing a ratio on a zero-width bar returns 0 for any x — silently writing the minimum of the range into whatever parameter that bar owns. This is not theoretical: it flattened a whole config section to its floor values during testing. Every drag handler tests bar.size.x < 2.0 first.

Polled, not awaited

A release outside the bar is never delivered to its gui_input; waiting for one let the scrub's drag flag latch on permanently, so a later hover kept scrubbing with nothing held down. _process polls the button instead.

SECTION 06Data Persistence, Safeguards & Self-Checks

6.1 Configuration

State lives in a single ConfigFile under user:// — on Windows, %APPDATA%\Godot\app_userdata\SOUNDSCAPE\.

var _cfg := "user://library_dev.cfg" if OS.has_feature("editor") else "user://library.cfg"

The editor and an exported build share user:// on one machine, so an editor save would otherwise be the first thing a shipped player sees. On a player's machine neither file exists yet, so the export always starts clean.

All 25 keys — verified to both load and save
SectionKeys
[library]folders, enabled_folders, known_folders, sort, tbs, shuffle, repeat

[effects] is written one entry per parameter rather than a single blob, so it stays readable and hand-editable like every other section — and everything is re-clamped on load rather than trusted, because a plain text file a user can edit will eventually contain an out-of-range value, and an out-of-range cutoff is an audible fault, not a caught error.

Two things are deliberately not persisted: Feed.FULLSCREEN (it would boot into a UI with no visible way out) and the [H] cursor-hidden state (same reason).

known_folders exists because the enabled set alone cannot distinguish “the user switched this off” from “this did not exist yet” — both are simply absent. Treating the second as the first is what made a freshly dropped album invisible with no error anywhere.

6.2 Factory reset

REBOOT arms on the first click (CONFIRM?) and commits on a second within 4 s. It resets every persisted setting: library roots, enabled/known folders, TBS list, sort, skin, username, EQ state and presets, all six visualizer parameters, boost, shuffle, repeat, beat tracking, layout, clock format, intro video, max FPS, feed size — and volume, fade, fade time, play delay, split fraction and the search filter, each pushing its widget back as well. A reset that leaves the UI showing old values is worse than one that skips.

Named default constants (VOLUME_DEFAULT 80.0, FADE_ON_DEFAULT true, FADE_MS_DEFAULT 1000, DELAY_MS_DEFAULT 250, SPLIT_FRAC_DEFAULT 0.5, FPS_DEFAULT 60) are shared between the config fallbacks and the reset, so the two cannot drift.

6.4 Headless harnesses

test_director.gd — godot --headless --path . --script res://test_director.gd. Synthesises click tracks at 90 / 120 / 128 / 174 BPM (55 ms kicks, 120 → 45 Hz pitch sweep with exponential decay — a sub-one-cycle blip is not a fair test signal), plays them, and asserts locked BPM within ±2.0 and mean phase error within ±30 ms, judging only the second half so the lock-in transient is ignored.

Load-bearing

Engine.max_fps matters there: headless Godot runs _process uncapped, which aliases against the audio mix callback and smears the song clock badly enough to look like a tracker bug.

Visual verification — --write-movie <dir>/f.png --fixed-fps 20 --quit-after N writes a numbered PNG sequence, so any screen can be inspected without adding debug drawing.

Caveat

The render opens a real window under the mouse, and stray input lands on whatever control is beneath it, silently rewriting persisted settings. Renders go to library_dev.cfg, so the real library is safe, but the dev config needs resetting after a render session.
